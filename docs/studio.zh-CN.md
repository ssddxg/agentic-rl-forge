# AgenticRLForge Studio 使用指南

Studio 是一个运行在你自己电脑上的 Agent 强化学习工作台。它把项目原有的 Search-R1、
轨迹执行、奖励计算、分组采样、评测与训练批次导出能力放进普通用户也能操作的网页。
在普通电脑上可以直接运行轨迹演示和完整离线数据管线；真正修改模型权重的 GPU 训练仍然
需要另外安装 PyTorch、verl，并准备模型服务。

本地知识库仍然保留，用来整理项目文档、检索语料和参考资料，但它是辅助功能，不是系统的
核心定位。运行记录、数据集、文档、索引和设置默认都保存在本机，应用不会向外发送使用
遥测；供运维排错使用的 Prometheus 指标只在本地服务中提供。

## 最简单的启动方式

### Windows

1. 安装 Python 3.10、3.11 或 3.12；安装时建议勾选“Add Python to PATH”。
2. 下载并解压项目。
3. 双击项目根目录的 `Start AgenticRLForge.cmd`。
4. 第一次启动会自动安装依赖，完成后浏览器会打开 <http://127.0.0.1:7860>。

以后仍然双击同一个文件即可。使用期间请不要关闭启动窗口；需要退出时在窗口里按
`Ctrl+C`。

### Linux 或 macOS

```bash
bash scripts/start-studio.sh
```

### Docker

```bash
docker compose up --build
```

打开 <http://127.0.0.1:7860>。Docker 数据保存在 `studio-data` 数据卷里，普通的容器重建
不会删除资料。

## 第一次使用：强化学习工作台

1. 打开“总览”，先查看“核心环境”和“训练环境”的状态。核心环境通过即可运行本地功能；
   没有安装 verl 并不影响入门演示。
2. 点击“运行轨迹演示”。系统会真实执行一次“问题 → 搜索工具 → 环境反馈 → 最终答案 →
   奖励”的智能体循环，并展示每一步的动作、观察、Token 和奖励。
3. 选择内置数据集，运行“离线 RL 数据管线”。它会生成分组轨迹，写入 SQLite 和分片，
   计算评测指标，筛选出有学习信号的样本，并导出经过校验的训练批次。
4. 需要验证自己的数据时，上传两个 UTF-8 JSONL 文件：问答数据与检索语料。示例格式：

```json
{"id":"q1","question":"法国首都是什么？","answer":"巴黎"}
{"id":"doc1","contents":"巴黎是法国的首都。"}
```

第一行是问答文件的记录格式，第二行是语料文件的记录格式。每行必须是一个完整 JSON 对象。

离线管线用于验证数据、轨迹、奖励、评测和训练输入是否连通，不会在后台假装训练模型权重。
页面只有在检测到 PyTorch 与 verl 后，才会把 GPU 训练环境显示为就绪。

## 辅助功能：本地知识库

1. 点击“新建知识库”，填写一个容易辨认的名字，例如“产品手册”或“课程笔记”。
2. 把文件拖到上传区域，也可以点击选择文件。
3. 等待文件状态变成“已就绪”。
4. 在输入框中输入问题或关键词，选择“搜索资料”即可查看匹配片段和文件出处。
5. 如果需要 AI 整理答案，先打开“模型设置”，保存并测试一个兼容 OpenAI 接口的模型，
   然后切换到“AI 问答”。

目前支持：PDF、DOCX、HTML、Markdown、reStructuredText 和纯文本。单个文件默认不能超过
25 MB；过大的文件建议先拆分。扫描版 PDF 如果没有文字层，需要先用 OCR 软件识别文字。

## 搜索与 AI 问答有什么区别

- “搜索资料”完全在本机运行，不需要账号或 API Key，结果是原文片段。
- “AI 问答”先搜索本地资料，再把命中的片段发送给你配置的模型服务，并显示引用来源。
- 如果资料里没有依据，模型被要求明确说明，而不是编造来源。
- 文档内容按不可信参考资料处理，不能通过文档里的指令修改系统规则。

使用在线模型时，命中的文字片段会发送到该模型服务。对隐私要求高时，可使用 Ollama、
LM Studio 或其他只在本机运行的 OpenAI 兼容服务。

## 模型设置

Studio 需要的是 OpenAI 兼容的聊天接口，常见地址示例：

- Ollama：`http://127.0.0.1:11434/v1`
- LM Studio：`http://127.0.0.1:1234/v1`
- 其他服务：填写服务商给出的基础地址和模型名称

API Key 以明文保存在本机 Studio SQLite 数据库中，浏览器读取设置时不会拿到密钥原文，
日志也不会记录密钥。留空会保留已有密钥；需要删除时请勾选“清除已经保存的 API Key”。
如果不能接受本地明文保存，请留空并使用无鉴权的本地模型，或使用操作系统的磁盘加密保护
Studio 数据目录。

## 数据位置与备份

默认数据目录：

- Windows：`%LOCALAPPDATA%\AgenticRLForge\Studio`
- macOS：`~/Library/Application Support/AgenticRLForge/Studio`
- Linux：`~/.local/share/agentic-rl-forge/studio`

备份前先停止 Studio，然后复制整个目录。恢复时也应先停止 Studio，再把完整目录放回原处。
不要只复制数据库文件，因为上传原件和搜索索引也在同一目录中。

需要指定其他位置时：

```bash
arf studio --data-dir /path/to/my-studio-data
```

## 常见问题

### 页面打不开

确认启动窗口仍在运行，并打开 <http://127.0.0.1:7860>。如果端口被占用，可以运行：

```bash
arf studio --port 7861
```

不要直接双击 `src/agentic_rl_forge/studio/static/index.html`。那只是应用内部的页面文件，
直接打开时没有本地 API 服务，功能无法运行；请始终使用启动器或 `arf studio` 打开网页。

### 文件一直处理失败

先确认扩展名受支持、文件没有损坏，并且不是只有图片的扫描 PDF。可以删除该文件后重新上传，
或点击重建索引。

### AI 连接测试失败

检查模型服务是否已经启动、接口地址和模型名称是否正确、API Key 是否有效。本地模型服务的
端口可能与上面的示例不同，以模型软件显示的地址为准。

### 可以让局域网其他设备访问吗

默认不可以，这是为了保护你的资料。只有明确了解风险时才使用非本机地址，并显式添加
`--allow-network`。不要直接把 Studio 暴露到公网；局域网共享场景应另外配置可信反向代理、
HTTPS 和访问控制。

## 命令行参数

```text
arf studio --data-dir PATH --host 127.0.0.1 --port 7860 --open
```

- `--data-dir`：更改数据保存位置。
- `--host`：监听地址，默认只允许本机。
- `--port`：浏览器访问端口。
- `--open / --no-open`：是否自动打开浏览器。
- `--allow-network`：非本机监听地址的显式安全确认。
